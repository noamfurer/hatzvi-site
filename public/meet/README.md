# העלאת המיני-סייט לאתר בית הספר (GitHub)

המדריך כתוב גם למי שאינו מתכנת. כל הפעולות נעשות בדפדפן, באתר GitHub, ואין צורך להתקין שום תוכנה.

**מה עושים:** מוסיפים לאתר הקיים תיקייה חדשה בשם `meet`. אחרי העלאה הדף יופיע בכתובת https://hatzvi.site/meet

**מה לא עושים:** לא משנים, לא מוחקים ולא מחליפים אף קובץ קיים. במיוחד לא נוגעים בקובץ `CNAME`, לא בהגדרות הדומיין ולא בהגדרות ה-DNS.

> לפני ההעלאה: ודאו שכבר הדבקתם את כתובת ה-Apps Script בקובץ `meet/js/config.js` (ראו `google-apps-script/README.md`).

---

## מבנה התיקייה

```
meet/
├── index.html                ← העמוד עצמו
├── README.md                 ← המדריך הזה
├── css/style.css             ← העיצוב (חל רק על העמוד הזה)
├── js/
│   ├── config.js             ← ההגדרות – הקובץ היחיד שבדרך כלל עורכים
│   ├── app.js                ← הטופס והאנימציות
│   └── boot.js               ← טעינה מוקדמת של האנימציות
└── assets/
    ├── og-image.jpg          ← התמונה שמופיעה בשיתוף בוואטסאפ/פייסבוק
    ├── flyer-original.jpg    ← הפלייר המקורי
    ├── erez-hatzvi-meet.ics  ← קובץ "הוספה ליומן" לאייפון/Outlook
    ├── images/               ← כל תמונות העמוד (WebP)
    ├── icons/                ← אייקון הדפדפן (Favicon)
    └── fonts/                ← הגופנים (שמורים מקומית – טעינה מהירה)
```

כל הנתיבים בעמוד מתחילים ב-`/meet/`, ולכן שום קובץ כאן לא משפיע על שאר האתר.

---

## שלב 1 – כניסה ל-Repository של האתר

1. היכנסו ל-https://github.com עם המשתמש שיש לו הרשאת עריכה לאתר בית הספר.
2. היכנסו ל-Repository של האתר. בדרך כלל זה זה שבתיקייה הראשית שלו יש קובץ בשם `CNAME` עם הטקסט `hatzvi.site`.
3. ודאו שאתם בענף (Branch) הראשי, שנקרא בדרך כלל `main`. השם מופיע בכפתור שמעל רשימת הקבצים, משמאל.
   - אם אינכם בטוחים איזה ענף מפרסם את האתר: **Settings → Pages**, תחת "Build and deployment", ושם רשום הענף.

## שלב 2 – העלאת תיקיית meet

1. ברשימת הקבצים של ה-Repository לחצו על **Add file ← Upload files**.
2. פתחו במחשב את התיקייה שבה נמצאת התיקייה `meet` (אחרי חילוץ קובץ ה-ZIP).
3. **גררו את התיקייה `meet` כולה** לתוך החלון של GitHub. גוררים את התיקייה עצמה, לא את הקבצים שבתוכה.
   - הגרירה עובדת בדפדפני Chrome ו-Edge במחשב.
   - GitHub ישמור את כל תתי-התיקיות כפי שהן.
4. חכו שכל הקבצים יסיימו להיטען. ברשימה צריכים להופיע נתיבים כמו `meet/index.html` ו-`meet/css/style.css`.

**אם הגרירה לא עובדת** (למשל בדפדפן Safari), אפשר להעלות שלב אחרי שלב:
- לחצו **Add file ← Create new file**. בשם הקובץ כתבו `meet/js/config.js` (הלוכסן יוצר תיקייה), והדביקו את תוכן הקובץ.
- לתמונות ולגופנים השתמשו ב-**Upload files** מתוך התיקייה המתאימה.
- בגלל שזה מסורבל, מומלץ להשתמש ב-Chrome במחשב.

## שלב 3 – שמירת השינויים (Commit)

1. בתחתית העמוד, בתיבה **Commit changes**, כתבו תיאור קצר, למשל: `הוספת מיני-סייט לערב ההיכרות`.
2. השאירו מסומן **Commit directly to the main branch**.
3. לחצו **Commit changes**.

## שלב 4 – לוודא שהפרסום הסתיים

1. לחצו בראש ה-Repository על הלשונית **Actions**.
2. בראש הרשימה תופיע ריצה בשם **pages build and deployment**.
3. חכו עד שתופיע לידה ✓ ירוקה. זה לוקח בדרך כלל 1–3 דקות.
   - ❌ אדומה = משהו נכשל. לחצו עליה כדי לראות את השגיאה (ראו "תקלות נפוצות").
   - אם אין לשונית Actions: חכו 3–5 דקות ועברו לשלב הבא.

## שלב 5 – לבדוק שהעמוד זמין

1. פתחו בדפדפן: **https://hatzvi.site/meet**
2. אם מופיעה שגיאה 404, חכו עוד כמה דקות ורעננו (Ctrl+F5 במחשב).
3. בדקו מהטלפון, ובמיוחד מתוך קישור שנשלח בוואטסאפ.

## שלב 6 – לוודא שהאתר הראשי לא נפגע

1. פתחו את **https://hatzvi.site** ובדקו שהדף הראשי נטען כרגיל.
2. פתחו גם עמודים נוספים, למשל `https://hatzvi.site/accessibility.html` ו-`https://hatzvi.site/terms.html`.
3. ב-GitHub, בלשונית **Commits**, ודאו שה-Commit האחרון כולל **רק** קבצים שמתחילים ב-`meet/`.

> ⚠️ **שימו לב:** נראה שלאתר הראשי יש כלי עריכה ופרסום משלו (כפתור "פרסום" בתוך האתר). אם הכלי הזה מפרסם את האתר מחדש על ידי החלפת כל הקבצים ב-Repository, הוא עלול למחוק את תיקיית `meet`. אחרי הפעם הבאה שתפרסמו שינוי באתר הראשי, ודאו שהכתובת hatzvi.site/meet עדיין עובדת. אם היא נמחקה, פשוט העלו את התיקייה שוב.

## עדכונים עתידיים

כדי לערוך קובץ ב-GitHub: פותחים את הקובץ, לוחצים על סמל העיפרון ✏️, עורכים, ובסוף לוחצים **Commit changes**. אחרי 1–3 דקות השינוי מופיע באתר.

| מה רוצים לשנות | איפה |
|---|---|
| כתובת ה-Apps Script | `meet/js/config.js` ← השורה `endpoint` |
| תאריך / שעה – לכפתור "יומן Google" ולשיתוף | `meet/js/config.js` ← `start`, `end`, `shareText` |
| תאריך / שעה – בטקסטים שבעמוד | `meet/index.html`. חפשו (Ctrl+F) את `23.12.2026` ואת `19:00` |
| תאריך / שעה – במסך התודה | `meet/js/app.js`. חפשו `23 בדצמבר` |
| תאריך / שעה – לאייפון/Outlook | `meet/assets/erez-hatzvi-meet.ics`. השעות בקובץ הן **בשעון UTC**: בחורף זה שעתיים פחות משעון ישראל (19:00 ← `170000Z`) |
| תאריך – בתיאור לשיתוף | `meet/index.html`, בראש הקובץ: `og:description`, `twitter:description`, `description` |
| טקסטים בעמוד | `meet/index.html`. מחפשים את הטקסט ומחליפים |
| תמונה | מעלים קובץ חדש **באותו שם בדיוק** לתיקייה `meet/assets/images/` (Upload files, ואז מאשרים החלפה). מומלץ פורמט WebP |
| תמונת השיתוף | מחליפים את `meet/assets/og-image.jpg` בתמונה בגודל 1200×630 |

> **תמונת השיתוף נשמרת בזיכרון של וואטסאפ ופייסבוק.** אחרי החלפה ייתכן שהתמונה הישנה תמשיך להופיע עוד זמן מה (ראו ההערה בקובץ README הראשי).

## הסרת המיני-סייט או החזרת גרסה קודמת

**הסרה מלאה:**
1. ב-Repository היכנסו לתיקייה `meet`.
2. לחצו על שלוש הנקודות **…** בפינה, ובחרו **Delete directory**. אם האפשרות לא מופיעה, מחקו כל קובץ בנפרד: פותחים אותו, לוחצים על **…**, ואז **Delete file**.
3. לחצו **Commit changes**. אחרי כמה דקות הכתובת /meet תפסיק לעבוד, והאתר הראשי לא יושפע.

**החזרת גרסה קודמת של קובץ:**
1. פתחו את הקובץ ב-GitHub ולחצו **History**.
2. בחרו את הגרסה הקודמת, ולחצו על **…** ואז **View file**. העתיקו את התוכן.
3. חזרו לגרסה הנוכחית, ערכו עם העיפרון ✏️, הדביקו את התוכן הישן, ולחצו **Commit changes**.

| 404 בכתובת /meet | הפרסום עוד לא הסתיים, או שהתיקייה הועלתה למקום אחר | חכו 5 דקות. ודאו שהקובץ נמצא ב-`meet/index.html` בתיקייה הראשית של ה-Repository ובענף שמפרסם את האתר |
| העמוד עולה בלי עיצוב ובלי תמונות | התיקייה הועלתה בשם אחר (למשל `Meet` או `meet-1`) | שם התיקייה חייב להיות בדיוק `meet`, באותיות קטנות |
| בשליחה מופיע "הטופס עדיין לא חובר" | לא הודבקה כתובת ב-`config.js` | הדביקו את כתובת ה-`/exec` ושמרו |
| בשליחה מופיע "הפרטים לא נשמרו" | בעיה בצד של גוגל | ראו "תקלות נפוצות" ב-`google-apps-script/README.md` |
| בוואטסאפ אין תמונה בתצוגה המקדימה | התצוגה נשמרה בזיכרון לפני שהאתר עלה | בדקו עם `?v=2` בסוף הכתובת |
| ריצה אדומה ב-Actions | שגיאה בבניית האתר (Jekyll) | פתחו את הריצה ובדקו את השגיאה. אם היא קשורה ל-`meet/README.md`, אפשר למחוק את הקובץ הזה מ-GitHub; הוא לא נחוץ לאתר |

**הרשאות:** כדי להעלות קבצים צריך הרשאת **Write** ל-Repository. כדי לראות את **Settings → Pages** צריך הרשאת **Admin**.
